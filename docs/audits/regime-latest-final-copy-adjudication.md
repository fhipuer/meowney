# 투자 레짐 최신 구현 최종 판정·반영 명세

작성일: 2026-08-16  
범위: v1.5.1 최신 코드의 거시·SEC CAPEX·공개 DRAM 표본·Snapshot/History·도움말  
원칙: 조기경보 목적, 계산과 표시의 일치, 30초 인지부하를 기준으로 채택 여부를 판정

## 최종 판정

최신 구현은 거시 조기경보 화면의 뼈대와 모바일 대응을 상당 부분 개선했다. 그러나 AI·메모리 영역은 확보한 데이터보다 넓은 개념을 이름과 상태로 주장하고 있고, 일부 provenance 문구는 실제 표시값과 일치하지 않는다. 이는 취향 문제가 아니라 사용자가 포트폴리오 상세점검 시점을 잘못 판단할 수 있는 계산·표시 계약 문제다.

이번 턴에는 **거짓으로 읽힐 수 있는 라벨을 축소하고, 결측을 0으로 그리지 않으며, 서로 다른 기간의 합계를 숨기고, 용어와 도움말을 정리하는 P0/P1 소규모 변경**을 수행하는 것이 맞다. 기업 공시를 공통 달력분기로 정렬하거나 AI 귀속 CAPEX를 분해하고, DRAM 대표성을 확장하는 일은 별도 데이터·스키마 작업으로 미룬다.

## 확정 제품 결정

### Snapshot 저장은 곧 현재 경보 확인이다

사용자 결정에 따라 다음 계약을 확정한다.

- `현재 상태 기록`을 누르면 당시 판정·원자료·활성 경보를 Snapshot으로 저장한다.
- 이 저장 행위 자체가 당시 활성 경보를 사용자가 확인했다는 의미다.
- 별도 `외부 상세점검 완료` 체크박스·버튼·설명은 두지 않는다.
- 이후 같은 경보 집합과 같은 심각도라면 `확인됨`으로 표시하고, 새 경보 또는 심각도 상승 시 다시 알린다.
- Snapshot 저장은 포트폴리오 분석을 앱이 실행했다는 뜻은 아니다. 그러나 이 부정형 문장을 본문에 반복하지 않고 Snapshot 도움말에서 의미를 짧게 정의한다.

따라서 과거 감사의 `Snapshot 저장과 경보 확인을 분리하라`는 의견은 **기각**한다. 현재 `create_snapshot()`이 `review_completed=True`를 저장하고 acknowledgment를 생성하는 v1.5.1 동작을 유지한다. UI에서 사라진 `/review-complete` API는 호환 사용처가 없음을 확인한 뒤 별도 정리할 수 있으나 이번 화면 판정 범위에는 포함하지 않는다.

## 핵심 지적별 판정

### A. 최신 수정값에 ‘초기 발표값’ 표시

**반드시 수용, P0.**

현재 `_indicator_rows()`는 최신 수정값 테이블 `regime_observations`의 최신 관측과, vintage 테이블의 가장 최근 timing row를 별도로 조회한 뒤 signal에 합친다. 두 값이 동일 observation/version이라는 보장이 없다. 프런트는 `vintage_kind === initial`이면 현재 표시값 옆에 `초기 발표값`을 붙이므로 provenance가 거짓일 수 있다.

이번 턴의 작은 변경:

- 현재 값에는 `초기 발표값` badge를 표시하지 않는다.
- 기본 표시는 `최신값`으로 한다.
- `available_from/release_date`도 현재 displayed observation과 연결이 검증되지 않으면 숨긴다.
- 도움말 문구: `현재 카드는 최신 저장값을 표시합니다. 초기 발표값과 수정 이력은 시점기준 이력에서 별도로 관리합니다.`

별도 데이터 작업:

- signal이 `displayed_observation_id` 또는 `(indicator_id, observation_date, available_from)`를 직접 참조하도록 한다.
- `latest_revised / initial / revised`를 값 version 단위로 반환한다.
- 값과 provenance가 같은 row에서 나온 경우에만 badge를 표시한다.

### B. 총 현금 CAPEX를 AI 투자로 단정하고 최신 분기를 단순합산

**핵심 비판 수용, 표현과 표시 로직은 즉시 재설계.**

SEC concept는 기업 전체 `PaymentsToAcquirePropertyPlantAndEquipment` 등 총 현금 CAPEX다. AI 전용 투자액이 아니다. 또한 `latest_period`가 회사마다 다른데 `latest_capex`를 합산해 `최근 분기 합계`로 표시한다. 상세 stacked chart는 period가 없는 회사를 `0`으로 채워 실제 0 지출처럼 보인다.

이번 턴의 P0/P1:

- 섹션명 `하이퍼스케일러 AI 투자` → `하이퍼스케일러 설비투자 프록시`.
- 첫 화면 `AI 인프라 투자 가설`은 유지하되 하위 라벨을 `총 현금 CAPEX 보조 신호`로 한다.
- `최근 분기 합계`는 즉시 삭제한다. 공통 기간 alignment가 확인된 경우에만 합계를 노출한다.
- 차트 결측은 `0`이 아니라 `null`/키 미생성으로 전달해 bar를 그리지 않는다.
- `분기 현금 CAPEX` → `기업별 분기 총 현금 CAPEX`.
- 상태명:
  - `확대 가속` → `CAPEX 증가 기업 우세·강함`
  - `높은 투자 지속` → `CAPEX 증가 기업 우세`
  - `감속 관찰` → `CAPEX 감소 기업 증가`
  - `혼조` 유지
  - `판정 불가` → `비교 자료 부족`
- `4개사 coverage` → `기업 자료 3/4`처럼 분수로 표시.
- 정확한 도움말: `SEC 공시의 기업 전체 현금 CAPEX입니다. AI 전용 투자액은 아니며 AI 투자 사이클의 보조 신호로 사용합니다.`
- 기업 카드에 반드시 `회계기간 종료 YYYY-MM-DD`를 값 바로 아래 표시한다.
- 서로 다른 회사의 최신값을 나란히 보여주되 합산하지 않는다.

별도 데이터·스키마 작업:

- calendar quarter와 fiscal quarter를 명시적으로 저장·정렬.
- 공통 기간에 발표가 완료된 회사만 합산한 `aligned_total`, `aligned_coverage`.
- 공시일 기준 provisional/final season 상태.
- 데이터센터·서버·AI 관련 CAPEX는 기업이 공식 분해해 공시한 경우에만 별도 metric으로 저장.
- 총 CAPEX에서 AI 귀속률을 임의 추정하지 않는다.

### C. 제한된 DDR5 표본을 ‘메모리 가격 사이클’로 과장

**수용, P0 카피 축소와 P1 상태 범위 제한.**

현재 상태는 DDR5 8GB SO-DIMM contract 한 종목을 핵심으로, DDR5 16Gb spot을 보조로 분류한다. 이는 공개 DRAM 표본이지 DRAM 전체, 서버 DRAM, HBM, NAND 또는 메모리 이익 사이클을 대표하지 않는다.

이번 턴:

- `메모리 가격 사이클` → `공개 DRAM 가격 표본`.
- `월간 DDR5 Contract를 핵심 가격 신호` → `DDR5 SO-DIMM 월간 계약가 표본을 기준으로, DDR5 현물가 표본을 함께 봅니다.`
- 상태명:
  - `가격 확장` → `SO-DIMM 가격 강한 상승`
  - `가격 상승` → `SO-DIMM 가격 상승`
  - `하락 관찰` → `공개 DDR5 표본 동반 하락`
  - `혼조` → `공개 DDR5 표본 혼조`
  - `가격 유지` → `SO-DIMM 가격 보합`
  - `판정 제한` → `표본 변화 확인 불가`
- 첫 화면에는 이 상태를 `메모리 사이클`로 승격하지 않고 `DRAM 가격 보조 신호`로 표시한다.
- 도움말: `공개 페이지에서 확인되는 일부 DRAM 제품 가격입니다. 서버 DRAM·HBM·NAND와 산업 전체 가격 사이클은 별도 자료가 필요합니다.`

별도 데이터 작업:

- Server DRAM, HBM, NAND contract/spot, inventory, bit shipment·supply의 신뢰 가능한 source registry.
- 제품·시장별 coverage와 대표성 metadata.
- 최소 두 독립 하위시장과 지속조건이 있기 전 `메모리 사이클` 종합상태를 만들지 않는다.

### D. 용어 혼재

**대부분 수용. 한글화 자체가 목적이 아니라 상태의 서로 다른 의미를 분리한다.**

정확한 용어 계약:

| 현재 | 대체 | 본문 의미 |
| --- | --- | --- |
| 자동 거시 레짐 | 확정 레짐 | 재확인 규칙까지 통과한 현재 상태 |
| 후보 경계 | 현재 후보: 경계 | 최신 자료로 즉시 계산한 미확정 상태 |
| 현재 경제환경 | 현재 경제상태 | 성장·물가 절대수준 |
| 최근 압력 | 최근 방향 | 최근 지표가 가리키는 성장·물가 방향 |
| 활성 임계 | 활성 경보 | 현재도 조건을 충족하는 경보 |
| 신규 경보 없음 | 활성 경보 없음 | count가 active trigger 수일 때 사용 |
| Snapshot 이후 상태 변화 | 기록 이후 변화 | 사용자 언어 |
| 데이터 품질 | 자료 상태 | 충분/제한/판정 불가 |
| coverage 100% | 핵심지표 34/34 | 수집 가용성 |
| History | 기록 | Snapshot 목록 |
| Snapshot | 상태 기록 | 버튼·탭의 사용자 용어 |

`Snapshot`은 Export나 도움말에서 기술명으로 한 번 병기할 수 있다: `상태 기록(Snapshot)`.

활성/신규 구분:

- trigger count는 `활성 경보 n개`다.
- 마지막 상태 기록 이후 처음 발생 또는 심각도 상승한 것만 `새 경보`다.
- 현재 API가 새/활성을 분리하지 못하면 본문에서 `새`를 쓰지 않는다.
- `review_acknowledged`이면 활성 경보에 `확인됨` badge를 붙이고 헤더는 `관찰 · 확인한 경보 유지`로 표현한다.

### E. 중복 본문과 누락 도움말

**수용하되 모든 설명을 숨기지는 않는다.**

본문에는 현재값의 해석과 다음 행동만 남긴다. 정의·방어문장은 (?) 도움말로 이동한다.

본문에서 이동/삭제할 문구:

- `점=절대수준 · 화살표=최근 압력` → 경제상태 제목 옆 도움말.
- `핵심지표 최신성 100%` → `핵심지표 34/34`로 바꾸고 정의는 도움말.
- `활성 임계신호는 Snapshot 이후 새로 생긴 것만을 뜻하지 않습니다` → 활성 경보 도움말.
- `주가 흐름은 CAPEX의 대체 데이터로 사용하지 않습니다` → CAPEX 도움말 안의 짧은 정의로 통합.
- `화살표는 실제 이동 경로나 전망치가 아닙니다...` → 차트 (?)로 이동.
- AI/DRAM 한계의 긴 부정형 문장 → 각 카드 제목 (?)로 이동.

본문에 유지할 문구:

- `관찰`
- `완만한 확장·물가 높음 / 최근 물가 완화·성장 변화 미미`
- `장기 실질금리 제한 구간`
- `다음 핵심 발표`
- 데이터 부족 시 구체적인 `자료 부족` 상태.

필수 도움말 7개:

1. 확정 레짐/현재 후보
2. 현재 상태 점/최근 방향 화살표
3. 활성 경보/새 경보/확인됨
4. 자료 상태/핵심지표 수
5. 상태 기록이 동결하는 값과 경보 확인 의미
6. 총 현금 CAPEX 프록시 범위
7. 공개 DRAM 표본 범위

### F. History 정보 부족

**수용, 기존 Snapshot JSON으로 가능한 부분은 이번 턴 P1.**

현재 기록 탭은 기록일, 자동/사용자 레짐, urgency, reasons 세 개만 보인다. 사용자가 “그때 무엇을 확인했고 지금 무엇이 달라졌는가”를 알기 어렵다.

이번 턴에 기존 필드로 추가:

- 제목: `2026-08-16 17:20 상태 기록`.
- badge: `확정 경계`, `당시 관찰`, `내 판단 유지/미입력`.
- 기준: `경제상태 기준일`, `기록시각`.
- 환경: 당시 `성장 수준 · 물가 수준 / 최근 방향`.
- 활성 경보: 당시 trigger 상위 3개와 총 개수.
- 산업 보조자료: `CAPEX 프록시 상태`, `DRAM 가격 표본 상태`.
- 사용자 메모.
- 접기/펼치기 상세에서 영역 상태, 자료 상태, rule version.

표시 문구:

- `이 기록을 저장하며 당시 활성 경보를 확인했습니다.`
- 별도의 `외부 상세점검 완료` 문구는 사용하지 않는다.

별도 작업:

- 직전 Snapshot과의 numeric diff, 경보 fired/resolved/severity_up 이력.
- 당시 provenance/version이 완전한 point-in-time 비교.

## 이번 턴 구현 범위

### P0: 반드시 반영할 카피·작은 표시 로직

1. 잘못 연결될 수 있는 `초기 발표값` badge 제거, `최신값`으로 표시.
2. CAPEX 결측을 0으로 그리지 않음.
3. 서로 다른 최신 회계기간의 `최근 분기 합계` 숨김.
4. AI 섹션을 `하이퍼스케일러 설비투자 프록시`, 차트를 `기업별 분기 총 현금 CAPEX`로 변경.
5. 메모리를 `공개 DRAM 가격 표본`으로 축소.
6. `자동/후보`, `활성/신규`, `품질/coverage`, `Snapshot/History` 용어 계약 반영.
7. Snapshot 도움말에 `저장 시 당시 활성 경보도 확인됨` 명시.
8. 본문의 중복 방어문장을 도움말로 이동.

### P1: 같은 턴에 가능한 표시 보강

1. History 카드에 기준일, 당시 환경, 활성 경보, CAPEX/DRAM 보조상태를 표시.
2. 기업별 CAPEX 카드에 회계기간을 값 바로 아래 배치.
3. 기업 coverage를 백분율보다 `3/4`로 표시.
4. `확인한 활성 경보` badge 표시.
5. 자료 상태를 `핵심지표 n/n`로 표시.
6. 차트·상태 제목에 누락된 (?) 도움말 추가.

## 별도 데이터·스키마 작업으로 미룰 범위

1. observation 최신값과 정확한 vintage row의 FK/복합키 연결.
2. initial/revised provenance를 값 version 단위로 노출.
3. 기업 fiscal/calendar quarter 정렬과 aligned aggregate.
4. AI 귀속 CAPEX 또는 공식 데이터센터 투자 분해.
5. AI 서비스 매출·수익화와 가이던스 구조화.
6. Server DRAM/HBM/NAND/재고/bit supply-demand.
7. Snapshot 간 수치·경보 lifecycle diff.
8. 산업 보조상태를 full investment regime으로 합성하는 규칙.

- 버튼: `현재 상태 기록`

## 수용 기준

1. 최신 수정값 카드에 `초기 발표값`이 표시되지 않는다.
2. CAPEX history 결측 period가 0 높이 bar나 합계에 포함되지 않는다.
3. 서로 다른 latest_period를 합친 숫자가 `최근 분기 합계`로 노출되지 않는다.
4. 화면 어디에도 총 현금 CAPEX가 AI 전용 CAPEX로 표현되지 않는다.
5. 공개 DDR5 SO-DIMM/spot만으로 `메모리 가격 사이클` 종합판정을 표시하지 않는다.
6. active trigger count 옆에는 `신규 경보 없음`이 아니라 `활성 경보 없음`을 사용한다.
7. coverage가 예측 신뢰도처럼 `품질 100%`로 표시되지 않는다.
8. Snapshot 저장 후 동일 trigger는 `확인됨`, 새 trigger/심각도 상승은 다시 점검 대상으로 표시된다.
9. 별도 `외부 상세점검 완료` 체크·문구가 나타나지 않는다.
10. History에서 기록시각, 기준일, 당시 레짐/urgency, 환경, 활성 경보를 확인할 수 있다.
11. 핵심 용어의 정의는 (?)로 접근 가능하고 본문에 부정형 방어문장이 반복되지 않는다.

## 기각 항목

- Snapshot과 경보 확인을 다시 분리하는 제안.
- AI·DRAM 섹션을 데이터가 불완전하다는 이유로 완전히 삭제하는 제안. 단, 명칭과 판정 범위를 축소한다.
- 모든 방법론 문구를 화면에서 제거하는 제안. 본문에서는 줄이고 (?)와 Export에 보존한다.
- SEC 총 CAPEX를 사용하지 말자는 제안. 총 CAPEX는 AI 전용 수치가 아니라는 전제 아래 breadth 보조 신호로는 유용하다.
- 공개 DRAM 가격을 무가치하다고 보는 제안. 대표성 badge와 범위 제한 아래 선행 보조표본으로 유지한다.

최종적으로 이번 수정은 모델을 더 복잡하게 만드는 작업이 아니라, **현재 계산이 실제로 말할 수 있는 범위까지만 UI가 말하게 만드는 작업**이어야 한다.
